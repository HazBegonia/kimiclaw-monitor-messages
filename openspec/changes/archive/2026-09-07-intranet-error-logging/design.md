## Context

当前监控器在 `main` 中捕获异常后只输出 stderr；`deliver_pending` 会吞掉重试异常。正常变化日志、版本快照和成功状态已经有稳定目录与原子写入约定，错误记录需要与这些业务日志隔离，并兼容常驻模式和 OpenClaw cron 的 `--once` 调用。

## Goals / Non-Goals

**Goals:**

- 建立统一的错误记录入口，覆盖扫描和持久化阶段。
- 让每条记录包含足够的诊断上下文，同时避免凭据和页面正文泄露。
- 保持失败时的 last-good state 语义，并让错误日志写入失败可回退到 stderr。
- 为后续 Claw skill 提供稳定、可检索的原始日志输入。

**Non-Goals:**

- 不改变网页轮询协议、调度频率或正常业务日志格式。
- 不由 Claw 判断业务重要性，不生成业务分析日志，不发送企业微信、钉钉或邮箱通知；这些属于后续 skill 的范围。
- 不引入第三方日志框架或后台服务。

## Decisions

### 使用独立的按日 JSONL 错误日志

错误日志写入 `logs/intranet-error/YYYY-MM-DD.log`，每行一个 JSON 对象，便于 PowerShell、Python 和后续 OpenClaw skill 按时间或阶段检索。选择按日文件而非每个错误一个文件，是为了避免高频失败时产生大量目录项；保留现有正常日志的时间戳命名约定不变。

每条记录包括 `detectedAt`、`monitorId`、`mode`、`phase`、`errorType`、`message`、脱敏后的 `url`、`path` 或 `eventId`（适用时）以及 `statePreserved`。消息限制为异常摘要，不写 traceback、响应正文或 Token；如需调试堆栈，依靠本地 stderr 或单独启用的开发诊断，不进入业务日志。

备选方案：使用 Python `logging` 默认旋转处理器。未采用，因为当前项目已有 Path 原子写入和工作区相对目录约定，直接实现小型 JSONL 写入更容易保持跨 Windows PowerShell/cron 的一致性，也不增加依赖。

### 在边界层标注失败阶段

不要求每个底层函数改变返回值，而是在配置加载、`run_once` 和 `main` 的边界捕获异常并传入阶段名。这样既能覆盖现有异常，也能避免为了日志而改动业务函数接口。

备选方案：让 Claw 解析 stderr 后再写原始错误日志。未采用，因为 stderr 可能缺少阶段和状态上下文，且 Python 启动或文件读取失败时容易丢失信息。Claw 后续只消费 Python 已写好的原始日志。

### 保持状态与正常日志的失败语义

错误记录发生在失败路径；只有网页抓取、校验、派生和所需持久化全部成功才更新成功状态。版本快照与状态写入的顺序需要调整为可诊断的事务边界：若任一步失败，错误记录说明阶段和路径，避免把部分快照当作成功扫描。若已经写出正常日志后状态写入失败，保留该日志但明确记录 `statePreserved`，后续任务可据此清理或重试。

### 错误记录失败时回退 stderr

错误日志写入器自身捕获文件系统异常，只输出一行脱敏摘要到 stderr，不再次递归记录。这样磁盘满或目录权限异常时仍有 OpenClaw/cron 可见的诊断信息。

### 当前阶段只提供原始日志

首版提供按日文件，并在运行文档中规定默认保留期和大小上限。日志中的 `eventId`、`phase` 和 `detectedAt` 供后续 Claw skill 去重、分类和生成业务分析日志使用；本 change 不实现这些后处理。

## Risks / Trade-offs

- [错误日志写入本身可能失败] → 回退 stderr，避免递归记录。
- [高频网络故障导致日志快速增长] → 按日 JSONL、消息截断，并设置保留期/大小上限。
- [正常日志先写、状态后写造成部分成功] → 明确持久化阶段和 `statePreserved` 字段；实现时尽量先完成可验证状态，再生成业务日志。
- [脱敏遗漏导致敏感信息进入异常消息] → 统一过滤 URL 查询参数、Authorization 字段和响应正文，只记录白名单上下文。

## Migration Plan

1. 新增错误日志目录和格式，不迁移或重写现有 `logs/intranet-diff`、`logs/intranet-focus` 文件。
2. 部署后先用 `--once` 人为制造超时和错误页面，确认错误日志、退出码及 last-good state。
3. 确认 Claw 或人工读取原始日志时能按 `eventId` 和时间定位错误；业务分析和通知暂不启用。
4. 若需回滚，停止使用错误日志读取方即可；删除错误日志功能不会影响现有状态文件和正常日志兼容性。

首版错误日志默认保留 30 天、总大小上限 100 MB；实现阶段以工作区内置常量或配置项承载，文档说明清理规则。该取值不影响错误记录字段和失败语义。
