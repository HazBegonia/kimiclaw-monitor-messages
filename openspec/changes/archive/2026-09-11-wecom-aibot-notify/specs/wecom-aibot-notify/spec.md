# wecom-aibot-notify 规格（delta）

## Purpose

将内网监控中经重要性判定后的关键消息（文件变更、监控错误），通过企业微信智能机器人长连接渠道实时推送到指定企业微信群，使责任人无需查看本地日志即可及时获知。

## ADDED Requirements

### Requirement: 企业微信智能机器人渠道建立

系统 SHALL 通过 OpenClaw 企业微信渠道（智能机器人长连接模式）建立到企业微信的出站连接，并支持向会话主动推送消息。机器人凭证（Bot ID、Secret）MUST 仅存于 OpenClaw 全局配置；项目仓库内 MUST NOT 出现明文 Secret。

#### Scenario: 渠道上线

- **WHEN** 使用正确的 Bot ID 与 Secret 完成渠道配置并重启 OpenClaw gateway
- **THEN** 渠道在 gateway 中显示在线，长连接建立成功

#### Scenario: 密钥不入库

- **WHEN** 检查项目仓库（含 git 历史）
- **THEN** 不存在机器人 Secret 的明文记录，项目内仅保存脱敏引用

### Requirement: 目标会话激活与标识持久化

系统 SHALL 在目标群成员与机器人完成首次交互（@机器人发送消息）后，获取该群会话的 chatid 并持久化到项目配置文件，作为后续主动推送的目标；chatid 不属于密钥，允许入库。

#### Scenario: 激活并记录 chatid

- **WHEN** 群成员在目标群 @机器人 发送任意消息
- **THEN** 系统从渠道回调中解析出该群的 chatid 并写入项目配置，后续推送以该 chatid 为目标

### Requirement: 重要监控消息推送

系统 SHALL 对监控产物做重要性判定；判定为重要的新增/删除文件变更（flow1）与监控错误（flow2）MUST 通过机器人主动推送到目标群会话。同一轮扫描产生的多条重要消息 SHOULD 聚合为一条推送。不重要或无变化的产物 MUST NOT 触发推送。

#### Scenario: 重要变更推送

- **WHEN** 一轮监控扫描产生新增文件且被判定为重要
- **THEN** 目标群在当轮处理完成后收到一条包含文件名与时间的推送消息

#### Scenario: 无重要变化不打扰

- **WHEN** 一轮监控扫描无变化或仅有被判定为不重要的产物
- **THEN** 目标群不收到任何推送

#### Scenario: 重要错误推送

- **WHEN** 监控错误日志中出现被判定为重要的错误记录
- **THEN** 目标群收到一条包含错误阶段与脱敏摘要的推送消息

### Requirement: 推送频控约束

系统 MUST 遵守企业微信推送频率限制（每会话 30 条/分钟、1000 条/小时）；当一轮重要消息超过限额时，系统 MUST 聚合或延迟发送而不是超限推送。

#### Scenario: 大量变更聚合

- **WHEN** 一轮扫描产生大量重要变更（如超过 20 个新文件）
- **THEN** 仅发送聚合后的少量消息，且不触发企微频控错误

### Requirement: 推送失败可观测

推送失败（网络异常、凭证失效、频控错误等）MUST 被记录到本地日志，包含失败原因与失败的消息内容，且不中断既有监控扫描流程。

#### Scenario: 推送失败留痕

- **WHEN** 向目标群推送消息失败
- **THEN** 本地日志出现一条包含错误码/异常信息与消息摘要的记录，监控扫描继续正常运行
