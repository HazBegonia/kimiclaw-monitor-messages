## Why

当前程序只比较网页目录中的文件名集合，无法表达“监控网页指定字段”的需求，也没有在变化后唤醒 OpenClaw。目标网页是无推送能力的静态目录页，因此需要一个常驻轮询器，在网页字段变化时产生日志并发出事件；无变化时不调用 Kimi。

## What Changes

- 将监控对象从硬编码文件名集合改为可配置的网页字段；默认字段为根目录 CSV 链接集合 `root_files`。
- 每隔可配置间隔请求目标网页，提取、规范化并比较字段快照。
- 首次成功请求只建立基线；后续仅在字段变化时生成本地 `.log`。
- 请求失败、错误页或不完整页面不得覆盖上次成功状态，也不得生成字段消失事件。
- 日志成功落盘后，提供可配置的本地 OpenClaw Gateway 事件接口；失败时保留待投递事件并重试。
- 监控程序作为常驻进程运行，Windows 任务计划只负责启动/守护，不使用 OpenClaw cron 反复启动 agent。
- 支持 1 秒、5 秒等轮询参数，并增加大页面解析与请求性能验证。
- 明确当前只能做到客户端轮询下的准实时；不实现服务端 SSE、WebSocket 或 Webhook 推送。
- 暂不处理企业微信、钉钉和 CSV 文件正文解析。

## Capabilities

### New Capabilities

- `intranet-web-field-monitor`: 轮询网页、提取配置字段、比较成功快照、生成变化日志并向 OpenClaw 发送事件。

### Modified Capabilities

无。

## Impact

- 修改现有 Python 监控程序及其状态、日志格式和运行参数。
- 新增字段配置、事件投递/待处理队列和重试机制。
- 扩展自动化测试与性能测试。
- 需要确定 OpenClaw Gateway webhook 的本地地址、鉴权方式和幂等约定。
- 当前 URL 每次约 1.33 MB；5 秒轮询约 22.9 GiB/天，1 秒轮询约 114.9 GiB/天。若后续提供轻量 manifest 或条件请求接口，可替换采集器降低流量。
