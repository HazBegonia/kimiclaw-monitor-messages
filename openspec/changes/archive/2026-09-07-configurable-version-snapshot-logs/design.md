## Context

现有 Python 监控器从目录 HTML 中提取根级 CSV 文件名，使用 `state/intranet-files.json` 保存最近一次成功快照，并仅在集合发生变化时写入 `logs/intranet-diff/*.log`。网页不提供推送接口，因此新能力继续复用同一次成功抓取，不读取 CSV 正文。

## Goals / Non-Goals

**Goals:**

- 用工作区配置声明可选版本及文件名匹配文本。
- 在一次抓取中同时产出通用变化结果和各选中版本的全量快照。
- 让快照日志可按版本分目录保存，避免与变化日志混淆。
- 保持失败时不更新成功状态、不写成功日志。

**Non-Goals:**

- 不改变内网网页抓取协议或轮询调度。
- 不下载 CSV 文件或解析 CSV 内部字段。
- 不实现重要性判断、企业微信、钉钉或邮箱投递。

## Decisions

### 配置驱动版本选择

使用工作区 JSON 配置中的 `selectedVersions` 数组，每项包含 `id` 与 `match`。选择 `match` 而不是把版本规则硬编码在 Python 中，便于公司增删版本；默认配置可为空或包含当前关注版本。

备选：为每个版本增加独立脚本。拒绝，因为会产生重复抓取和重复状态管理。

### 单次抓取、多路派生

一次成功下载并解析目录后，先得到全量 CSV 文件名集合，再按每个版本的 `match` 文本过滤。这样多个版本不会增加 HTTP 请求次数，且通用变化日志与版本快照使用同一成功页面。

备选：每个版本单独请求网页。拒绝，因为页面约 1.33 MB，会线性放大网络流量。

### 日志分层

继续使用 `logs/intranet-diff/` 保存仅有变化的全局日志；新增 `logs/intranet-focus/<version-id>/` 保存每次成功扫描的版本快照。快照文件采用现有 Windows 安全时间戳命名，并在同一毫秒追加序号。

### 状态兼容

全局比较状态继续保存完整 `root_files` 集合。版本快照不改变全局状态格式；如需防止配置版本变更造成历史误读，快照本身记录匹配文本和当前文件列表，版本 ID 作为目录和日志中的稳定标识。

## Risks / Trade-offs

- [每次成功扫描都会增加日志数量] → 只记录文件名和元数据，不记录 HTML/CSV 内容；按版本分目录，后续可增加保留策略。
- [简单包含匹配可能误匹配相似标识] → 配置中的 `match` 由公司维护，日志记录实际匹配文本；若未来需要严格边界，再扩展匹配类型。
- [版本配置为空时没有版本快照] → 通用变化日志仍可工作，文档明确空列表语义。

## Migration Plan

1. 新增版本配置并先填入 `103300110002`，执行一次单次扫描确认日志格式。
2. 检查 `logs/intranet-focus/103300110002/` 中的全量文件名。
3. 按需增加或移除 `selectedVersions` 项，无需改代码。
4. 回滚时清空版本列表或恢复旧程序；`state/intranet-files.json` 和通用变化日志保持兼容。
